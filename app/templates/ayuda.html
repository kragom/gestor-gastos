Ayuda y funcionamiento

Cómo trabaja Balance por dentro y qué revisar si algún día algo falla.

Cómo se usa (flujo diario)

  1. Añadir movimientos: con el botón ＋ (barra inferior en móvil) o «＋ Añadir». Registras gasto, ingreso o transferencia con importe, cuenta y categoría.
  2. Movimientos programados: en Programados defines gastos/ingresos que se repiten cada mes o año. Los automáticos se crean solos; los de propuesta te los ofrece para confirmar.
  3. Presupuestos: fijas un límite por categoría y ves cuánto llevas gastado.
  4. Reintegrables: gastos que esperas recuperar (p. ej. un adelanto). Se marcan aparte y luego como «reintegrado».
  5. Gráficos: resumen visual por categorías y evolución.
  6. Cuentas y Categorías: configuras tus bancos/efectivo y las categorías con su color e icono.

Qué servicios usa la app

Balance es una PWA (app instalable) construida con FastAPI (Python). Se apoya en cuatro servicios gratuitos. Todos son independientes: si uno falla, aquí sabrás cuál mirar.

AlojamientoRender

Es el servidor donde corre la aplicación (la web que estás viendo). Si la app no carga o da error de servidor, casi siempre el problema está aquí.

Panel: dashboard.render.com → tu servicio web → pestaña Logs para ver el error, y Manual Deploy para reiniciarla.

Base de datosHugging Face (Dataset)

Tus datos (movimientos, cuentas, etc.) viven en un archivo SQLite que se guarda y sincroniza en un dataset privado de Hugging Face. Render, al reiniciarse, borra su disco; por eso la base de datos se respalda ahí para no perder nada.

Si ves datos «antiguos» o vacíos tras un reinicio, revisa que la sincronización con Hugging Face funcione (token válido).

CódigoGitHub

El código fuente de la app está en un repositorio de GitHub. Cada vez que se sube un cambio ahí, Render se actualiza y despliega la nueva versión automáticamente.

Es también la «copia maestra» del proyecto: si Render se perdiera, se puede volver a desplegar desde aquí.

Mantener despiertaGitHub Actions

El plan gratuito de Render «duerme» la app si no se usa. Una tarea programada (GitHub Actions) la visita cada pocos minutos para mantenerla activa, así carga rápido cuando entras.

Si al abrir tarda 30-60 s la primera vez, es que estaba dormida; es normal y no es un fallo.

El camino de tus datos

Tu móvil/navegador → Render (la app) → guarda en SQLite → respaldo en Hugging Face.

Un cambio de código → GitHub → despliegue automático en Render.

GitHub Actions cada pocos minutos → «toca» Render → la app no se duerme.

Si algo falla: por dónde empezar

SíntomaDónde mirar
La web no abre o da error de servidorRender → Logs (y reiniciar con Manual Deploy)
Tarda mucho solo la primera vezNormal: estaba dormida. Revisa GitHub Actions si es constante
Faltan datos o parecen desactualizadosSincronización con Hugging Face (token del dataset)
Subí un cambio y no apareceGitHub (que el cambio esté subido) → Render (que el deploy terminó)
Cambios de diseño no se ven en el móvilCierra y reabre la PWA un par de veces (caché del navegador)

Consejo de seguridad: los accesos (tokens) de GitHub, Render y Hugging Face son privados. Si alguna vez se filtran, puedes regenerarlos desde el panel de cada servicio y actualizarlos en la configuración de Render.
